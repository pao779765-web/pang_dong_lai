# R5 混合检索对照实验

**结论：** R5A 安全门槛通过；暂不接入 Worker，不部署。

## 实验配置

- 向量服务：腾讯云 TokenHub
- 模型：`kinfra-text-embedding-0.6b`
- 维度：1024
- 文档向量：135 个
- 普通检索许可：96 个
- 案例受限：39 个
- 融合：BM25 锚定 + RRF 补充，向量权重 0.65
- 密钥：只从本地环境变量读取，未写入索引、评测结果或 Git

## 两轮结果

| 轮次 | 通过 | 回归 | 严重回归 | 结论 |
|---|---:|---:|---:|---|
| 首轮纯 RRF | 50/54 | 4 | 2 | 不通过 |
| 第二轮 BM25 锚定 | 54/54 | 0 | 0 | 安全门槛通过 |

首轮失败题为 `C3-04`、`C5-01`、`C6-01`、`C6-06`。问题不是逐题答案，而是三类通用机制缺口：纯向量重排会挤出 BM25 已验证的边界材料；纯背景片段会因语义相近被单独引入；“投诉奖励”用途识别要求出现“顾客”二字，覆盖口语不足。

第二轮采用三项通用修正：

1. 保留 BM25 已验证的前五项，只用 RRF 向量候选补足空位；
2. `context_only` 纯背景片段不能由向量单独引入；
3. “投诉＋奖励/金额”统一进入顾客投诉奖励用途过滤，不依赖问题必须出现“顾客”。

固定 54 题最终为 54/54，案例路由、禁用片段隔离、终局意图和资料不足安全均无退步。完整逐题结果见 `pangdonglai_project/evaluation/rag-culture-r5-hybrid-experiment.json`。

## 尚未证明的部分

当前 54 题只能证明混合检索没有破坏既有能力。由于 BM25 控制组已经是 54/54，本试卷无法衡量向量带来的新增收益。下一步需要冻结一套未参与现有规则调试的语义改写影子题；只有影子题显示真实提升且继续零严重退步，才讨论接入本地 Worker。
