# 总体方案

> 稳定文档：只在产品方向变化时更新。详细产品方案见 `pangdonglai_project/PRODUCT_PLAN.md`，执行状态见 `docs/HANDOFF.md`。

## 目标

在本仓库建立 **Codex + Grok** 双 Agent 协作流程，并完成“胖东来文化数字馆”项目：借助公开可核验资料、门店与媒体档案、证据链和可追溯 AI，让外界更深入理解胖东来“自由·爱”的企业文化。

## 产品主线

产品采用“**从印象到证据，再到对话**”的叙事：

1. 首页用大众和媒体印象关键词吸引注意。
2. 通过文化地图、门店图谱、报道档案和证据链建立理解。
3. 通过标明来源、时间与不确定性的非官方 AI 资料助手继续探索。

## 原则

1. 同一本地路径，两边打开同一文件夹。
2. 用 `docs/HANDOFF.md` 做交接报告，用 Git 做工作边界。
3. Codex 主实现；Grok 主来源核验、环境验证与质量验收；用户拍板。
4. 所有确定性内容可追溯；网络标签与待核验内容不得冒充事实。
5. 图片、新闻、商标和地图遵守授权与平台规则。
6. AI 明确标识为非官方资料助手，无证据时不猜测。
7. 不再直接向压缩后的旧 HTML 追加多轮覆盖脚本；开发阶段先恢复可维护源码。

## 技术选型（推荐，待用户批准后执行）

- 前端：Vite + React + TypeScript + React Router
- 样式：整理后的 Tailwind CSS 或 CSS Modules，二选一
- 第一版内容：TypeScript/JSON 静态数据
- 第一版地图：地址 + 高德/百度地图深链，不接 SDK
- AI 阶段：服务端 API + 白名单资料库 + RAG；模型和部署平台后定

## 协作分工

- **Codex**：源码重建、视觉与交互、门店/新闻/AI 功能实现、测试与修复。
- **Grok**：官方信息与媒体来源核验、diff 审查、构建与多设备测试、来源和 QA 报告。
- **用户**：文案与视觉拍板、图片授权、地图/AI/部署选择和最终验收。

## 风险与注意

- 避免两边同时修改同一文件。
- 当前 HTML 是用户已有原型且尚未纳入 Git；在用户确认开发前不移动、不重命名、不覆盖。
- 现有页面引用缺失的 `hero-bg.png`，且存在多轮 Hero 覆盖脚本，不能作为长期源码继续扩展。
- 门店营业时间与数量可能变化，页面必须显示来源和最后核验日期。
- 新闻只链接原文并写原创短摘要，不复制全文或无授权图片。
- 禁止提交模型密钥、地图 Key、Token、`.env` 和账号凭据。
