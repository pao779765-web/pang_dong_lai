# 移动端验收清单

> 对应一 / 二 / 三期手机适配。改 UI 后至少过一遍「冒烟」；发版前建议过「完整」。  
> 线上域名以 CloudBase 当前服务为准（见 `docs/HANDOFF.md`）。

## 视口建议

| 代号 | 逻辑宽度 | 说明 |
|---|---:|---|
| S | 360–375 | 小屏安卓 / iPhone SE 量级 |
| M | 390–430 | 主流手机 |
| L | 768 | 平板竖屏 / 大屏折叠展开 |
| D | 1280+ | 桌面对照 |

工具：Chrome 设备模式 + **至少一台真机**（优先微信内置浏览器）。

---

## A. 冒烟（每次 UI 改动后，约 5 分钟）

- [ ] 首页 200，主标题「理解胖东来 / 从理解人开始」可读
- [ ] **无整页横向滚动**（S/M）
- [ ] Hero A/B 按钮各一整行、不重叠、可点
- [ ] 门店展开后图片显示（本站 `/stores/...`，非裂图）
- [ ] AI 区仅 **一套** 输入 + 发送（无「结构示例」第二套）
- [ ] 发送一条短问题，能收到流式回答或明确错误提示
- [ ] 键盘 Tab 可见焦点环（桌面）；跳过链接「跳到正文内容」可聚焦

## B. 一期基础可用（S/M）

- [ ] viewport 按设备宽度缩放（非桌面缩略全页）
- [ ] 安全区：刘海/底部横条不挡顶栏与输入
- [ ] 主按钮 / 章节 / 发送 / 建议 chip 热区大约 ≥44px
- [ ] 正文约 ≥14–15px；输入框 **≥16px**（iOS 不整页放大）
- [ ] 地址、长链接可折行

## C. 二期产品化（S/M）

- [ ] 关键词入场后基本静止（不持续乱飘）
- [ ] 章节卡片全宽、易点
- [ ] 门店图高度合适；地图按钮好点
- [ ] AI：消息区可滚、输入贴对话窗底部；发送后滚到底
- [ ] 来源链接可点区域够大
- [ ] 对话区不在视野时出现「去提问」FAB；进入对话区后消失
- [ ] 矮屏横屏：Hero 不过分占高（可选）

## D. 三期工程质量

- [ ] 门店图带 `width`/`height`/`sizes`，减少布局跳动
- [ ] 建议 chip、地图链接、来源、FAB 有 `:focus-visible`
- [ ] `prefers-reduced-motion: reduce` 时动画明显减弱
- [ ] 本地 `npm test` 通过
- [ ] （发版时）CloudBase 新版本 100% 流量后再测一次线上

## E. 已知禁区 / 回归点

| 风险 | 说明 |
|---|---|
| 双 AI 界面 | 禁止再渲染 `dialogue-window-prototype`；窄屏勿用裸 `.dialogue-window { display:flex }` 覆盖 `display:none` |
| 官网图床 | 门店图必须本站 `/stores/`，勿改回 `web.azpdl.cn/upload` 直链 |
| 微信缓存 | 发版后需强刷或重开页 |

## 自动化对应

仓库内测试（`site/tests/rendered-html.test.mjs`）会检查：

- 一期：viewport 相关、16px 输入、safe-area、760/390
- 二期：对话 flex、FAB、480、触屏 hover 取消、无结构示例
- 三期：skip-link、门店 `sizes`、`content-visibility`、扩展 focus-visible

自动化**不能替代**真机与微信内置浏览器手测。
