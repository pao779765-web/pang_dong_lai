# 胖东来互联网资料检索与 RAG 入库规范

> **适用对象：Codex、Grok**
>
> **状态：强制执行**
>
> **生效日期：2026-07-30**

## 1. 目的

本规范用于持续检索、审核和整理互联网上与胖东来有关的公开资料，并将合格内容安全地加入网站 RAG 知识库。

目标不是尽可能多地收集网页，而是建立一套可以长期重复、能够说明资料边界、不会把初步说法误写成最终结论的资料生产流程。

Codex 或 Grok 在执行以下工作前，必须先完整阅读本文件：

- 搜索胖东来相关互联网资料；
- 审核用户或另一位协作者提供的链接；
- 新建或修改来源审核文件；
- 将资料写入 `pangdonglai_project/knowledge-base.json`；
- 调整与资料检索、事件结论或来源展示有关的逻辑。

如本规范与用户在当前任务中的明确要求冲突，以用户的明确要求为准，并在 `docs/HANDOFF.md` 记录原因和处理结果。

---

## 2. 核心原则

### 2.1 搜索结果不能直接进入正式知识库

无论资料来自人工搜索、搜索引擎、自动监测还是批量脚本，都必须先进入候选资料流程。

禁止：

- 搜到网页后直接写入正式知识库；
- 因为标题看起来相关就直接引用；
- 用自动化程序绕过人工审核和用户批准；
- 用资料数量代替资料质量。

### 2.2 正式知识库只收录用户批准的资料

资料经过核实后，必须标记为以下状态之一：

- `candidate`：候选资料，尚未完成审核；
- `approved`：可按审核范围正式使用；
- `limited`：只能用于指定问题、指定事实或指定事件阶段；
- `rejected`：不采用。

只有用户明确批准的 `approved` 或 `limited` 内容才能进入正式知识库。

### 2.3 只保存自写摘要与必要事实

正式知识库保存：

- 自己整理的事实摘要；
- 必要的短语级事实信息；
- 原始网页标题、发布者、日期和链接；
- 适用范围、事件阶段和回答限制。

不得整篇复制新闻、图书、视频文稿或其他受版权保护的内容。

### 2.4 自动化只能扩大候选池

定时搜索、网页监测、RSS、搜索 API 或其他自动工具，只能生成候选资料清单，不能自动批准、自动入库或自动发布。

---

## 3. 资料主题分类

每一轮只集中处理一个主题，禁止以“胖东来全部信息”为单次任务范围。

统一使用以下六类主题：

1. **企业文化与价值观**

   员工待遇、休假制度、管理方式、经营理念、顾客理念。

2. **企业制度如何落地**

   退换货、客诉处理、商品质量、食品安全、供应商管理、服务流程。

3. **人物与公开访谈**

   于东来及企业管理层的公开讲话、企业原文、权威媒体专访。

4. **热点事件**

   用户反馈、媒体报道、企业回应、调查进展、监管或司法结论。

5. **门店与业务变化**

   新开店、闭店、营业调整、帮扶调改、自有品牌和业务布局。

6. **社会影响与外部评价**

   政府文件、法院材料、学术研究、行业分析和其他企业的学习实践。

---

## 4. 来源查找顺序

同一事实应优先寻找最初发布者，不把转载数量当作独立证据数量。

查找顺序如下：

1. 胖东来企业官网、官方账号、企业原始公告；
2. 政府部门、市场监管部门、法院等公开文件；
3. 人民日报、新华社等权威媒体的原创报道或专访；
4. 高校、研究机构、正式出版物和有明确作者的行业研究；
5. 其他能够核实作者、日期和原始出处的媒体报道；
6. 社交平台内容。

社交平台内容原则上只能用于发现线索、确认舆情存在或记录当事人公开反馈，不能单独证明争议事实成立，也不能单独支撑最终结论。

## 5. 搜索与候选筛选

### 5.1 搜索方式

围绕一个主题组合关键词，例如：

```text
胖东来 + 员工休假
胖东来 + 客诉处理
胖东来 + 商品质量 + 官方回应
胖东来 + 事件名称 + 市场监管
胖东来 + 于东来 + 专访
site:web.azpdl.cn + 关键词
site:gov.cn + 胖东来 + 关键词
```

搜索时记录搜索日期。涉及热点事件时，应按时间分别搜索事件起因、企业回应、后续进展和最终结论。

### 5.2 企业身份核验

标题中出现“胖东来”不代表资料一定与本项目所研究的胖东来商贸集团有关。

每条资料至少核对：

- 企业主体是否为胖东来商贸集团有限公司或其明确关联主体；
- 门店是否为官网列出的许昌、新乡门店或有明确证据的相关项目；
- 事件、人物和官方账号是否能够对应；
- 是否只是名称相似的其他商家。

身份无法确认的资料不得入库。

### 5.3 原始来源与转载去重

发现多家网站报道相同内容时：

- 优先保留最初报道或最接近当事方的原始来源；
- 记录其他报道是否增加了独立采访、文件或新事实；
- 单纯转载、改写标题或重复引用同一公告的网页不算独立证据；
- 必要时在审核记录中说明传播链条。

## 6. 候选资料卡片

每条候选资料至少记录：

```text
候选编号：
标题：
网页地址：
发布者：
发布时间：
访问日期：
所属主题：
涉及案例：
企业身份是否确认：
是否为原始来源：
它明确支持哪些事实：
它不能证明什么：
当前属于哪个事件阶段：
是否与其他资料冲突：
自写摘要：
建议状态：
建议使用范围：
```

候选卡片不得只写“可信”或“不可信”，必须说明它能支持什么、不能支持什么。

批量资料建议使用 JSONL 或 CSV 保存候选清单；面向用户的审核结论继续使用 Markdown，方便阅读和批准。

---

## 7. 热点事件的强制规则

热点事件统一按以下时间顺序整理：

```text
用户或当事人反馈
→ 媒体报道
→ 企业初步回应
→ 企业或监管调查进展
→ 监管、司法或其他可核验的最终结论
```

### 7.1 最终结论限制

- 没有最终结论资料时，回答只能说明“目前公开进展到哪里”；
- 企业的初步回应不能被写成监管结论、司法结论或事实终局；
- 媒体转述企业说法时，必须明确归因于企业或媒体；
- 后续出现新结论时，不能覆盖或删除早期阶段，应补充事件时间线；
- 事件轨没有 `final` 资料时，禁止使用“已经证实”“最终查明”“事件结论是”等终局话术。

### 7.2 事件轨与文化轨分开

- **事件轨**：回答具体发生了什么、企业怎么回应、进展到哪一步；
- **文化轨**：解释企业制度、价值观和处理方式可能体现的文化特征。

文化轨不得裁定具体客诉的真伪，也不能用企业文化评价代替事件证据。

---

## 8. 审核与用户批准

每轮建议：

1. 搜索 20～30 个结果；
2. 删除明显重复、同名企业、无法访问和没有原始出处的结果；
3. 保留约 10 条候选资料；
4. 深度审核其中 5～8 条；
5. 形成简明审核清单交给用户；
6. 等待用户逐条或按批次批准；
7. 仅处理用户批准的范围。

审核结论必须说明：

- 建议 `approved`、`limited` 还是 `rejected`；
- 可回答哪些问题；
- 不可回答哪些问题；
- 是否可以支持最终结论；
- 与知识库已有资料是否重复或冲突。

---

## 9. 正式入库

入库前确认：

- 用户已经批准；
- 来源身份和链接已经核实；
- 自写摘要没有超出原文；
- 案例资料具有正确的 `caseId`；
- `claimType` 与事实类型一致；
- `finality` 与事件阶段一致；
- `approved` 与 `limited` 的使用范围已经写清；
- 没有整篇复制受版权保护的内容；
- 没有密钥、Token、账号信息或个人敏感信息。

入库后必须：

1. 对相近资料去重；
2. 为新主题或新事件增加测试问题；
3. 测试正确召回、错误召回和无资料回答；
4. 特别测试是否错误输出最终结论；
5. 运行项目现有测试与 lint；
6. 更新 `docs/HANDOFF.md`；
7. 经确认后再部署新版本。

本地知识库更新不会自动改变已经部署的云端网站，必须完成测试和重新部署后才会生效。

## 10. Codex、Grok 与用户分工

### Grok

- 广泛搜索候选资料；
- 查找原始出处和不同说法；
- 核对网页可访问性、发布者、日期与事件时间；
- 发现同名企业、重复转载和相互冲突的资料；
- 输出候选卡片与审核建议；
- 不得未经用户批准直接写入正式知识库。

### Codex

- 维护资料结构、案例结构和审核规范；
- 对候选资料进行去重和字段统一；
- 将用户批准的资料整理为自写摘要并入库；
- 完善检索、回答边界和回归测试；
- 更新交接记录，并在测试通过后执行发布；
- 不得把搜索结果或 Grok 的建议视为用户已经批准。

### 用户

- 决定每轮资料主题和优先级；
- 批准、限制或拒绝候选资料；
- 验收问答效果；
- 决定正式发布时机。

## 11. 向量库接入条件

向量库不替代来源审核，也不替代正式知识库。

建议满足以下条件后再接入：

- 已积累约 30～50 份经过批准的高质量资料；
- 资料主题、案例和事件阶段字段基本稳定；
- 已建立能够持续运行的问答测试集；
- 普通检索的错误召回和最终结论边界已有测试保护。

推荐顺序：

```text
候选资料池
→ 审核与用户批准
→ 正式知识库
→ 问答测试集
→ 关键词与向量混合检索
```

向量检索只能帮助找到语义相近的内容，不能判断企业身份、资料真伪、转载关系或事件是否已有最终结论。

---

## 12. 推荐的首批主题

首批优先处理“企业文化如何具体落地”，包括：

- 员工休假与工作制度；
- 顾客投诉和反馈处理；
- 退换货与售后制度；
- 商品质量与食品安全管理；
- 供应商和自有商品管理；
- 服务细节及其背后的经营原则。

这批资料应以企业原始说明、权威专访、政府或监管公开资料为主。完成首批资料和测试后，再扩大到热点事件与行业评价。

- 本规范由 Codex 与 Grok 共同遵守；
- 任何人修改本规范前，必须先说明修改理由；
- 涉及“谁可以批准资料”“是否允许自动入库”“最终结论规则”的修改，必须得到用户明确同意；
- 每次修改都要同步更新 `docs/HANDOFF.md`。
