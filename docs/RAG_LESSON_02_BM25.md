# RAG 第二课：用 BM25 给资料排序

## 本课目标

上一课的资料已经分成可以回答小问题的 `chunks`。这一课不改变资料内容，而是把“找哪一段资料”的简单关键词重合规则，升级为 BM25 排序。

BM25 仍然是**关键词检索**，不是向量检索；它不会理解所有同义说法，但会比“谁重合的词多就排前面”更稳定。

## 当前代码在做什么

代码位于 `pangdonglai_project/site/worker/index.ts`，由四个部分组成：

| 函数或常量 | 通俗作用 |
| --- | --- |
| `makeSearchTerms` | 把一句中文按连续两个字拆成小词，例如“周二闭店”变成“周二”“二闭”“闭店”。 |
| `BM25_K1` | 控制同一个词重复出现时，分数增长多快。当前值 `1.2` 是常见起点。 |
| `BM25_B` | 控制对长资料片段的平衡程度。当前值 `0.75` 是常见起点。 |
| `scoreBm25` | 计算“这个问题”和“这一条资料”的 BM25 分数。 |
| `searchKnowledge` | 给所有资料片段打分，按高到低取前三条。 |

## BM25 比上一版多考虑了什么

1. **词在资料中出现次数**：一个词出现多次通常更相关，但不会无限加分。
2. **词是否稀有**：如果“周二”只出现在一条资料中，它比每条资料都有的“胖东来”更有区分度。
3. **资料长度**：长片段包含更多字，不能仅因为长就天然得分更高。

例如用户问“胖东来周二是否闭店”：

- “周二闭店说明”包含“周二”“闭店”，并且这些词在其他地址片段中较少出现，因此应排在最前。
- “许昌与禹州门店地址”“新乡门店地址”即使也含有品牌名称，得到的区分性分数也更低。

## 它还不做什么

- 不生成向量；
- 不需要向量数据库；
- 不理解完全不同的同义说法；
- 不会直接调用 DeepSeek。

下一步是在 `handleChat` 中调用 `searchKnowledge(用户问题)`，并把前三条资料以“证据”的形式交给 DeepSeek。DeepSeek 负责表达，BM25 只负责选资料。
