# RAG 第一课：资料不是“喂给模型的文本”，而是可核验的证据

## 本课目标

完成这一课后，你会知道：

1. RAG 为什么先解决“资料从哪里来”，再解决“模型怎么回答”。
2. 一条可进入知识库的资料，至少要记录哪些信息。
3. 怎样用三条小而可靠的资料，为下一课的本地 RAG-Lite 做准备。

本课**不改网站代码、不上传云端、不调用 DeepSeek**。

---

## 1. 用一句话理解 RAG

RAG（检索增强生成）不是训练一个新模型，而是在提问时先从你的资料库里找出相关证据，再把“问题 + 证据”交给 DeepSeek 组织答案。

```text
你的问题
  ↓
从资料库找相关内容（检索）
  ↓
把证据连同问题发送给模型
  ↓
模型基于证据回答，并标明来源
```

所以，RAG 的可靠性首先取决于资料：如果资料来源不清、已过期，或把观点当事实，模型再聪明也会给出不可靠的回答。

---

## 2. 五个最重要的词

| 词 | 通俗解释 | 本项目中的例子 |
| --- | --- | --- |
| 来源（source） | 信息最初发布的页面或文件 | 官网页面、媒体原报道链接 |
| 文档记录（document） | 我们为一条来源建立的“资料卡” | 标题、链接、来源类型、核验日期、摘要 |
| 片段（chunk） | 适合回答一个小问题的短段落 | 一段 100–200 字、只讲一个主题的摘要 |
| 元数据（metadata） | 帮助筛选和追溯资料的标签 | 官方/媒体、发布日期、主题、核验状态 |
| 检索（retrieval） | 在回答前，从资料卡中找最相关的片段 | 用户问“门店服务”，系统先找服务主题资料 |

模型负责表达；资料卡负责让表达有依据。

---

## 3. 哪些资料可以先进入候选池？

优先级从高到低：

1. 企业或门店的官方原始页面、公开声明、正式发布内容。
2. 有明确媒体主体、作者或编辑部、发布时间的原报道。
3. 研究机构、学术或权威行业报告的原文页面。
4. 社交媒体、转述文章、评论区：只能作为“某种观点存在”的线索，不能直接当作事实依据。

无论来源类别如何，候选资料都要满足：

- 有可打开的原始链接；
- 能看出发布主体；
- 记录你核验的日期；
- 摘要把“事实”和“观点/评价”分开写；
- 不整篇复制新闻报道。我们只保存自己写的简短摘要和原始链接，以尊重版权。

资料不够时，宁可让 AI 说“资料库目前没有足够证据”，也不要用不明资料补全答案。

## 4. 一张合格的资料卡长什么样？

下面只是结构示例，`example.com` 和内容均非真实胖东来资料：

```json
{
  "id": "official-culture-001",
  "title": "示例：企业文化页面",
  "sourceType": "official",
  "url": "https://example.com/culture",
  "publishedAt": null,
  "verifiedAt": "YYYY-MM-DD",
  "summary": "由资料整理者根据原文写的 100—200 字摘要；事实与观点分开说明。",
  "topics": ["企业文化"],
  "status": "approved"
}
```

字段解释：

- `sourceType`：先只用 `official`、`media`、`research`、`other` 四种。
- `publishedAt`：原页面看得到就填写；看不到就保持 `null`，不能猜。
- `verifiedAt`：你最后一次检查链接和内容的日期。
- `summary`：自己写的短摘要，不复制长文章。
- `status`：`candidate` 是候选，`approved` 是审计后可用，`rejected` 是不采用。

## 5. 你的 15 分钟练习

请找 **最多三条** 候选来源：

1. 一条官方网站或公开发布页面；
2. 一条与门店、服务或经营实践有关的原始页面；
3. 一条有明确新闻机构的媒体原报道。

你只需把每条的 **标题 + 链接** 发给我；不要粘贴整篇新闻或长段原文。

我们将用下面四个问题审核它：

1. 谁发布的？
2. 链接是否指向原始页面，而不是二次转载？
3. 能否确认发布日期或至少确认核验日期？
4. 其中哪些是事实，哪些只是评价或观点？

当三张资料卡的信息完整、并由你确认后，它们才会成为知识库的第一批内容。
