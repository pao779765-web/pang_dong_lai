# “自由与爱”文化 RAG 建设路线图

> **适用对象：Codex、Grok、用户**
>
> **状态：当前 RAG 主路线图**
>
> **更新日期：2026-08-03**
>
> **资料检索与入库同时受 `docs/RAG_RESEARCH_PROTOCOL.md` 约束**

## 1. 最终目标

本项目的 RAG 不是普通的“胖东来资料查询器”，而是要帮助广大网友从具体做法、公开证据、企业回应和外部观察中，更深入地理解胖东来“自由与爱”的企业文化。

理想回答应帮助用户完成以下理解路径：

```text
看到一种具体做法
→ 明白为什么这样做
→ 理解它体现的价值观
→ 看见员工、顾客、商品与经营之间的关系
→ 同时知道资料边界、现实限制和可能争议
```

网站不负责证明“胖东来一定好”，也不把文化口号当作事实证据。它应让用户能够依据可追溯资料形成自己的判断。

---

## 2. 当前阶段判断

当前系统处于“可工作的、带来源约束的 RAG 原型”阶段，已经完成技术闭环，但尚未形成完整的文化解释体系。

### 已有基础

- 网页聊天、流式输出与来源展示已经可用；
- 本地 BM25 能从已审核资料中选择知识片段；
- 具体事件与一般文化问题已分轨；
- 初步回应、企业调查、监管结论和司法结论具有边界约束；
- 无资料时要求克制回答；
- 接口已有输入长度、频率、并发和超时保护；
- 当前知识库包含 30 份资料、135 个知识片段和 6 个案例；
- 已完成目录化资料层：manifest、来源元数据、正文位置、JSONL 切片和独立案例；
- 现有 41 项自动测试在 2026-08-03 通过；
- 已完成 30 份来源的正文权限处理：24 份为 `partial_text`，6 份因原件缺失、页面不可定位或版权边界保留 `summary_only`。

### 主要缺口

1. “自由与爱”本身尚无完整、专门的知识主线；
2. 当前 30 份资料均已完成入库边界处理，其中原有 23 份已完成终轮正文审计；仍有 6 份只有审核摘要，后续只有取得企业原帖、法院原文、稳定正文或明确授权后才能继续升级；
3. 员工制度、信任授权、顾客关系、品质管理和经营节制等主题的一手资料不足；
4. 冻结 BM25 基线为 28/54（51.8%）；上下文、终局、已知资料缺口、Query 改写和回答用途过滤依次启用后，当前固定试卷达到 54/54，召回、路由、隔离、终局和无答案安全均通过；
5. 当前仍以连续双字 BM25 为底层，语义能力来自审核规则和领域词表；54/54 只说明当前固定试卷通过，不代表任意新问法、任意事实请求或通用资料充分性判断都已解决；
6. 回答已增加 Claim、AnswerPlan 与 AnswerValidation 通用控制层；第三轮真实 DeepSeek 18 题已由第二轮 12/18 升至 15/18，热点事件和资料不足均满分，但最小事实可用性、必要区分覆盖和单案外推边界仍待完善；
7. 正式文化知识地图、54 道试卷、冻结基线与当前对照结果均已建立；下一步仍应依据失败清单补资料与文化知识字段，在错别字、语义召回和通用充分性判断稳定前不接入向量库。

## 3. “自由与爱”文化地图

后续资料搜索、知识卡片和测试题统一围绕六条文化主线组织。

### C1 — 员工的尊严、自由与生活

重点问题：

- 企业如何看待员工的完整人格和个人生活？
- 休假、工作时间、不开心假、薪酬福利等制度如何运行？
- 员工自由与组织纪律如何平衡？
- 媒体印象、企业自述与可核验制度之间有什么区别？

### C2 — 信任、一线授权与责任

重点问题：

- 为什么让一线员工拥有处理问题的权力？
- 授权如何与培训、责任和纠错机制配套？
- 信任是文化口号，还是能够观察到的组织机制？

### C3 — 顾客关系与真诚服务

重点问题：

- 退换货、投诉处理、投诉奖和服务细节为什么存在？
- “顾客至上”是否等于无条件满足所有要求？
- 真诚服务与表面话术有什么区别？

### C4 — 商品、品质与供应链

重点问题：

- 品质、价格、供应商和企业信誉之间是什么关系？
- 企业如何公开说明食品安全或商品争议？
- 企业自检、监管结论和消费者反馈应如何区分？

### C5 — 利润、规模与经营节制

重点问题：

- 企业如何公开表述利润、规模、扩张和幸福之间的关系？
- 为什么“不盲目扩张”常被视为其文化的一部分？
- 价值表达与实际经营结果应如何分开核验？

### C6 — 争议中的文化检验

重点问题：

- 面对客诉和舆论争议时，企业是否公开、负责、尊重和理性？
- 企业回应、内部调查、监管结论、司法结论分别能说明什么？
- 具体争议能否检验企业文化，又为什么不能直接证明整个文化真伪？

## 4. 总体推进顺序

```text
文化地图
→ 网友问题评测集与当前基线
→ 现有来源的正文权限与覆盖审计
→ 六条主线的资料补齐
→ 文化知识卡片结构
→ Query 改写 V1
→ 文化型回答结构
→ 关键词 + 向量混合检索
→ 真实用户试用
→ 稳定发布与持续更新
```

不得因为某项技术容易展示而打乱依赖顺序。特别是：在资料主干、评测集和字段结构未稳定前，不优先接入向量库。

## 5. 分阶段执行计划

### 阶段 R0 — 文化地图与评测基线

**目标：** 先定义“系统应该帮助用户理解什么”，再测量当前能力。

交付物：

1. 六条文化主线的正式问题地图；
2. 40～60 道“网友问题试卷”；
3. 当前 BM25 的基线结果；
4. 资料缺口、检索错误和生成越界三类问题清单；
5. 更新或替代过时的 `docs/RAG_LESSON_03_EVALUATION.md`。

测试题至少覆盖：

- 直接问题；
- 同义表达；
- 口语表达；
- 上下文追问；
- 常见错别字；
- 质疑性问题；
- 具体事件与文化问题的隔离；
- 最终结论问题；
- 知识库没有答案的问题；
- 容易误召回其他主题的问题。

建议测试记录字段：

```text
问题 ID
对话上下文
当前问题
所属文化主线
预期事件轨或一般轨
预期案例
应该召回的知识片段
绝对不能召回的知识片段
是否询问最终结论
是否应明确资料不足
实际结果
失败类型
```

验收标准：

- 每条文化主线至少有 6 道测试题；
- 正例、负例和追问题都有明确预期；
- 跑出当前系统基线，不用主观感觉代替结果；
- 在基线完成前不修改 Query 改写算法。

### 阶段 R1 — 六条文化主线的资料主干

**目标：** 先回填现有资料中允许保存的具体内容，再用经过批准的新资料补齐“自由与爱”的核心证据。

原有 23 份资料已经完成以下审计；后续每次新增资料仍应逐项复用这些检查：

- 原始页面是否仍可访问；
- 是否允许保存完整正文、部分正文或只能保存元数据；
- 当前摘要覆盖了哪些部分、遗漏了哪些部分；
- 正文回填后应怎样按章节或自然段切片；
- 是否存在版本变化、失效链接或需要替换的原始来源。

每轮执行：

1. 只选择一条文化主线；
2. 搜索 20～30 个结果；
3. 去掉同名企业、转载、失效页和无法确认原始出处的内容；
4. 保留约 10 条候选资料；
5. 深度审核 5～8 条；
6. 交给用户批准、限制或拒绝；
7. 依据权限写入规范化正文或必要片段，摘要只作为导航；
8. 生成可定位到正文的检索切片；
9. 为新增资料增加正例、负例和边界测试。

资料优先顺序：

```text
企业原始资料
→ 政府、监管、法院公开材料
→ 人民日报、新华社等原创报道或专访
→ 高校、正式出版物与行业研究
→ 其他可核验媒体
→ 社交内容只作线索或受限材料
```

第一批从 **C1 员工的尊严、自由与生活** 开始，随后依次推进 C3、C4、C2、C5、C6。

阶段目标：

- 累计 30～50 份经过用户批准的高质量资料；
- 每条文化主线至少具有 3 份能够互相补充的 L1/L2 资料；
- 不能只依靠一本书、一次访谈或单个热点事件解释整套文化；
- 每份资料都说明能回答什么、不能证明什么；
- 每份资料具有明确的 `metadata_only`、`summary_only`、`partial_text` 或 `full_text` 状态。

### 阶段 R2 — 文化知识卡片结构

**目标：** 让知识库不仅保存“发生了什么”，还能支持“为什么与文化有关”。

目录化底座已经完成：

```text
manifest
→ sources/<id>/metadata.json + content.md
→ chunks/<id>.jsonl
→ cases/<id>.json
→ 构建时生成兼容索引
```

> **2026-08-02 状态：字段落库与首次对照实验完成。** 现有 135 个正式片段均已写入 `culture-v1`，构建阶段会拒绝漏标或越界标注；结构、统计与边界见 `docs/RAG_CULTURE_ANNOTATION_V1.md`。直接把非案例文化字段拼入 BM25 由控制组 39/54 降至 38/54、隔离由 51/54 降至 50/54，因此实验开关不用于网站正式检索；详见 `docs/RAG_CULTURE_BM25_CULTURE_V1_EXPERIMENT.md`。

在现有文档、案例和事件阶段字段基础上，评估增加：

```text
cultureTheme：所属文化主线
practice：可观察到的具体做法
mechanism：做法如何运行
valueMeaning：它可能体现的价值取向
stakeholders：涉及员工、顾客、供应商或管理者
tension：现实限制、冲突或不同观点
effectiveAt：资料对应的时间
```

以上是内部结构，不在用户界面展示专业字段。

验收标准：

- 同一主题下能够对比企业自述、媒体观察和第三方分析；
- 具体事件不能因为标记了文化主题而被用来裁定整个文化真伪；
- 现行制度和历史资料能够按时间区分；
- 旧知识片段迁移后原有测试继续通过。

### 阶段 R3 — Query 改写 V1

**目标：** 让普通网友不必使用知识库中的标准词汇。

> 2026-08-01 用户明确要求提前处理其中的上下文、终局意图与资料不足噪声。该受限子阶段已完成并保留 28/54 冻结基线作对照。2026-08-02 的规则式文化主线识别达到 54/54，但在原 BM25 候选上做 3%～20% 重排均保持 39/54，没有新增通过，故未启用。随后完成固定领域错字修正与 10 条审核口语/同义扩展：相较启用前控制组 39/54，Query 改写 V1 达到 50/54、零退步。回答用途过滤 V1 又区分文化与薪酬、经营表现与文化复制、顾客投诉奖与员工委屈奖，并拦截未指定案例的企业自行送检终局问题；当前固定试卷达到 54/54，已进入本地正式检索，云端尚未重新部署。

第一版优先采用可测试的规则与领域词表，不增加额外模型调用。

能力范围：

- 结合前文，把“那后来呢”补成独立问题；
- 保留上一轮的事件或文化主题；
- 扩展经过审核的同义词；
- 修正常见错别字；
- 从口语问题中提取事件、主题和最终结论意图；
- 同时保留原始问题，避免改写偏离用户意思；
- 改写失败时安全回退到原问题。

验收标准：

- 评测集中直接问题召回保持稳定；
- 追问和同义表达的正确召回明显提高；
- 不增加跨案例误召回；
- 无资料问题仍然能够明确拒答；
- 最终结论边界测试 100% 通过。

### 阶段 R4 — 文化型回答结构

**目标：** 从“资料复述”升级为“帮助理解”。

> **2026-08-02 用户确认：** “回答—做法—文化逻辑—边界”只作为内部设计，不直接展示给普通用户。面向用户统一使用更自然的“简单说—具体来看—为什么这么做—还要分清”。这四步是回答组织原则，不要求每次机械显示四个标题；短问题可以自然合并，但不能省略必要的事实边界。

> **2026-08-03 首轮真实回答：** 三种回答契约接入 Worker 后，18 道 DeepSeek 调用 18/18 成功，但严格内容验收仅 10/18：热点事件 5/5，一般文化 4/10，资料不足 1/3。失败集中在时间错误、无关案例、遗漏关键区分和单向文化裁定；详见 `docs/RAG_CULTURE_R4_LIVE_EVALUATION.md`。

> **2026-08-03 回答控制 V1 与第二轮实测：** 不再为八道失败题逐题追加提示词补丁。现有 135 个审核片段已确定性生成 135 个 `claim-v1`；每次问题由检索结果动态生成 AnswerPlan，模型首稿再经 AnswerValidation 检查。第二轮真实调用 18/18 成功，严格验收由 10/18 升至 12/18；一般文化 6/10、资料不足 3/3，但校验误报使事件题降至 3/5，三道原通过题回归。下一步先修复数字/编号、否定语境和最小事实安全降级，仍不进入 R5；详见 `docs/RAG_CULTURE_R4_LIVE_EVALUATION_ROUND2.md`。

> **2026-08-04 回答控制 V1.1 通用修复：** 列表编号与事实数字分开识别，资料日期和来源标题进入数字依据；绝对结论检查识别明确否定语境；有允许 Claim 时安全降级保留排名最高的最小事实。原 Top-5 BM25 评测口径保持不变，回答规划层可在同一安全过滤后的 Top-12 候选中按文字相关度、原检索分数和“机制/争议边界”等通用证据意图选择最多 5 条 Claim；Claim 新增必要区分字段，当前明确区分顾客投诉奖励、员工委屈奖励和法院判决赔偿。固定检索 54/54、R4 自动契约 18/18、43 项测试与 lint 通过；未调用第三轮 DeepSeek、未部署、仍不进入 R5。

> **2026-08-04 第三轮真实评测与用户决定：** 同一 18 题调用 18/18 成功，严格验收由 12/18 升至 15/18；一般文化 7/10、资料不足 3/3、热点事件 5/5。第二轮三道回归全部修复且没有新增回归。剩余三类问题记录为通用质量债务。用户明确接受 AI 回答仍有不完美，不要求围绕每道失败题持续增加专用代码，并批准 R4 以“有限通过”进入 R5；这不表示幻觉已经解决，也不授权部署。

一般文化问题采用：

```text
简单说：先用一两句话直接回答，不用资料说明开场
→ 具体来看：选择一至三个最相关、可核验的做法或例子
→ 为什么这么做：解释它与员工、顾客、经营和“自由与爱”的关系
→ 还要分清：自然说明时间、适用范围、资料限制、现实争议或不同观点
```

内部结构与大众表达的对应关系：

| 内部约束 | 面向用户的表达 | 要求 |
|---|---|---|
| 回答 | 简单说 | 先回答问题，不绕弯，不把来源清单当作答案 |
| 做法 | 具体来看 | 只举直接支持当前问题的真实做法，避免堆砌资料 |
| 机制与价值 | 为什么这么做 | 用人与经营的关系解释，不用抽象口号代替分析 |
| 归因与边界 | 还要分清 | 说明资料是谁的说法、对应什么时间，以及不能推出什么 |

热点事件问题采用：

```text
这件事现在知道什么
→ 企业当时怎么处理
→ 后来有没有明确结论
→ 这件事让我们观察什么
```

热点事件最后一步只能把公开、负责、尊重、纠错等作为观察企业文化的问题，不能用文化口号裁定具体客诉真伪；企业回应、媒体报道、监管结论和司法结论仍须分开表达。

验收标准：

- 第一段直接回答用户，不以“根据资料库检索”或来源分级开场；
- 通常只选择一至三个最相关例子，并解释这些例子为什么与用户的问题有关；
- “为什么这么做”必须落到员工、顾客、经营或责任关系，不写成口号复述；
- “还要分清”使用自然语言，不堆免责声明，但不能省略会改变结论的重要限制；
- 不向普通用户暴露 L1/L2、`caseId`、`finality` 等内部术语；
- 不只堆来源或免责声明；
- 不将媒体、图书观点改写成企业官方事实；
- 不把回答写成单向赞美；
- 能自然呈现证据、质疑、限制和文化理解。

### 阶段 R5 — 关键词与向量混合检索

## 6. 协作分工

### Codex

- 维护文化地图、知识结构、评测集和检索代码；
- 把用户批准资料转换为文化知识卡片；
- 实现 Query 改写、混合检索和回答边界；
- 运行测试、记录基线、更新 HANDOFF 并部署；
- 不得把 Grok 的审核建议视为用户已经批准。

### Grok

- 按文化主线广泛寻找候选资料；
- 核实企业身份、原始出处、发布日期、转载关系和事件阶段；
- 寻找相反材料、现实边界与不同观点；
- 输出候选卡片和审核建议；
- 独立复核评测结果、检索误召回和改动 diff；
- 不得未经用户批准直接写入正式知识库。

### 用户

- 决定文化主线优先级；
- 批准、限制或拒绝候选资料；
- 判断回答是否真正帮助理解，而不是只有技术正确；
- 参与试用验收并决定发布时机。
