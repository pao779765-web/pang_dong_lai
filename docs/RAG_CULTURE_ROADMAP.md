# “自由与爱”文化 RAG 建设路线图

> **适用对象：Codex、Grok、用户**
>
> **状态：当前 RAG 主路线图**
>
> **更新日期：2026-08-01**
>
> **资料检索与入库同时受 `docs/RAG_RESEARCH_PROTOCOL.md` 约束**

## 1. 最终目标

本项目的 RAG 不是普通的“胖东来资料查询器”，而是要帮助广大网友从具体做法、公开证据、企业回应和外部观察中，更深入地理解胖东来“自由与爱”的企业文化。

理想回答应帮助用户完成以下理解路径：

```text
看到一种具体做法
→ 明白为什么这样做
→ 理解它体现的价值观
→ 看见员工、顾客、商品与经营之间的关系
→ 同时知道资料边界、现实限制和可能争议
```

网站不负责证明“胖东来一定好”，也不把文化口号当作事实证据。它应让用户能够依据可追溯资料形成自己的判断。

---

## 2. 当前阶段判断

当前系统处于“可工作的、带来源约束的 RAG 原型”阶段，已经完成技术闭环，但尚未形成完整的文化解释体系。

### 已有基础

- 网页聊天、流式输出与来源展示已经可用；
- 本地 BM25 能从已审核资料中选择知识片段；
- 具体事件与一般文化问题已分轨；
- 初步回应、企业调查、监管结论和司法结论具有边界约束；
- 无资料时要求克制回答；
- 接口已有输入长度、频率、并发和超时保护；
- 当前知识库包含 30 份资料、135 个知识片段和 6 个案例；
- 已完成目录化资料层：manifest、来源元数据、正文位置、JSONL 切片和独立案例；
- 现有 31 项自动测试在 2026-08-01 通过；
- 已完成 30 份来源的正文权限处理：24 份为 `partial_text`，6 份因原件缺失、页面不可定位或版权边界保留 `summary_only`。

### 主要缺口

1. “自由与爱”本身尚无完整、专门的知识主线；
2. 当前 30 份资料均已完成入库边界处理，其中原有 23 份已完成终轮正文审计；仍有 6 份只有审核摘要，后续只有取得企业原帖、法院原文、稳定正文或明确授权后才能继续升级；
3. 员工制度、信任授权、顾客关系、品质管理和经营节制等主题的一手资料不足；
4. 冻结 BM25 基线为 28/54（51.8%）；用户明确要求先解决上下文、终局意图与资料不足噪声后，当前同题集结果为 39/54（72.2%），上下文追问题和终局意图均通过，无答案安全由 0/6 提升到 6/6；
5. 当前仍依赖连续双字 BM25，错别字案例路由和一般文化问题的语义错配尚未解决；资料充分性闸门目前只覆盖已确认的结构化资料缺口，不是通用事实判断器；
6. 回答虽然较克制，但还没有稳定形成“做法—机制—价值—边界”的文化理解路径；
7. 正式文化知识地图、54 道试卷、冻结基线与当前对照结果均已建立；下一步仍应依据失败清单补资料与文化知识字段，在错别字、语义召回和通用充分性判断稳定前不接入向量库。

## 3. “自由与爱”文化地图

后续资料搜索、知识卡片和测试题统一围绕六条文化主线组织。

### C1 — 员工的尊严、自由与生活

重点问题：

- 企业如何看待员工的完整人格和个人生活？
- 休假、工作时间、不开心假、薪酬福利等制度如何运行？
- 员工自由与组织纪律如何平衡？
- 媒体印象、企业自述与可核验制度之间有什么区别？

### C2 — 信任、一线授权与责任

重点问题：

- 为什么让一线员工拥有处理问题的权力？
- 授权如何与培训、责任和纠错机制配套？
- 信任是文化口号，还是能够观察到的组织机制？

### C3 — 顾客关系与真诚服务

重点问题：

- 退换货、投诉处理、投诉奖和服务细节为什么存在？
- “顾客至上”是否等于无条件满足所有要求？
- 真诚服务与表面话术有什么区别？

### C4 — 商品、品质与供应链

重点问题：

- 品质、价格、供应商和企业信誉之间是什么关系？
- 企业如何公开说明食品安全或商品争议？
- 企业自检、监管结论和消费者反馈应如何区分？

### C5 — 利润、规模与经营节制

重点问题：

- 企业如何公开表述利润、规模、扩张和幸福之间的关系？
- 为什么“不盲目扩张”常被视为其文化的一部分？
- 价值表达与实际经营结果应如何分开核验？

### C6 — 争议中的文化检验

重点问题：

- 面对客诉和舆论争议时，企业是否公开、负责、尊重和理性？
- 企业回应、内部调查、监管结论、司法结论分别能说明什么？
- 具体争议能否检验企业文化，又为什么不能直接证明整个文化真伪？

## 4. 总体推进顺序

```text
文化地图
→ 网友问题评测集与当前基线
→ 现有来源的正文权限与覆盖审计
→ 六条主线的资料补齐
→ 文化知识卡片结构
→ Query 改写 V1
→ 文化型回答结构
→ 关键词 + 向量混合检索
→ 真实用户试用
→ 稳定发布与持续更新
```

不得因为某项技术容易展示而打乱依赖顺序。特别是：在资料主干、评测集和字段结构未稳定前，不优先接入向量库。

## 5. 分阶段执行计划

### 阶段 R0 — 文化地图与评测基线

**目标：** 先定义“系统应该帮助用户理解什么”，再测量当前能力。

交付物：

1. 六条文化主线的正式问题地图；
2. 40～60 道“网友问题试卷”；
3. 当前 BM25 的基线结果；
4. 资料缺口、检索错误和生成越界三类问题清单；
5. 更新或替代过时的 `docs/RAG_LESSON_03_EVALUATION.md`。

测试题至少覆盖：

- 直接问题；
- 同义表达；
- 口语表达；
- 上下文追问；
- 常见错别字；
- 质疑性问题；
- 具体事件与文化问题的隔离；
- 最终结论问题；
- 知识库没有答案的问题；
- 容易误召回其他主题的问题。

建议测试记录字段：

```text
问题 ID
对话上下文
当前问题
所属文化主线
预期事件轨或一般轨
预期案例
应该召回的知识片段
绝对不能召回的知识片段
是否询问最终结论
是否应明确资料不足
实际结果
失败类型
```

验收标准：

- 每条文化主线至少有 6 道测试题；
- 正例、负例和追问题都有明确预期；
- 跑出当前系统基线，不用主观感觉代替结果；
- 在基线完成前不修改 Query 改写算法。

### 阶段 R1 — 六条文化主线的资料主干

**目标：** 先回填现有资料中允许保存的具体内容，再用经过批准的新资料补齐“自由与爱”的核心证据。

原有 23 份资料已经完成以下审计；后续每次新增资料仍应逐项复用这些检查：

- 原始页面是否仍可访问；
- 是否允许保存完整正文、部分正文或只能保存元数据；
- 当前摘要覆盖了哪些部分、遗漏了哪些部分；
- 正文回填后应怎样按章节或自然段切片；
- 是否存在版本变化、失效链接或需要替换的原始来源。

每轮执行：

1. 只选择一条文化主线；
2. 搜索 20～30 个结果；
3. 去掉同名企业、转载、失效页和无法确认原始出处的内容；
4. 保留约 10 条候选资料；
5. 深度审核 5～8 条；
6. 交给用户批准、限制或拒绝；
7. 依据权限写入规范化正文或必要片段，摘要只作为导航；
8. 生成可定位到正文的检索切片；
9. 为新增资料增加正例、负例和边界测试。

资料优先顺序：

```text
企业原始资料
→ 政府、监管、法院公开材料
→ 人民日报、新华社等原创报道或专访
→ 高校、正式出版物与行业研究
→ 其他可核验媒体
→ 社交内容只作线索或受限材料
```

第一批从 **C1 员工的尊严、自由与生活** 开始，随后依次推进 C3、C4、C2、C5、C6。

阶段目标：

- 累计 30～50 份经过用户批准的高质量资料；
- 每条文化主线至少具有 3 份能够互相补充的 L1/L2 资料；
- 不能只依靠一本书、一次访谈或单个热点事件解释整套文化；
- 每份资料都说明能回答什么、不能证明什么；
- 每份资料具有明确的 `metadata_only`、`summary_only`、`partial_text` 或 `full_text` 状态。

### 阶段 R2 — 文化知识卡片结构

**目标：** 让知识库不仅保存“发生了什么”，还能支持“为什么与文化有关”。

目录化底座已经完成：

```text
manifest
→ sources/<id>/metadata.json + content.md
→ chunks/<id>.jsonl
→ cases/<id>.json
→ 构建时生成兼容索引
```

本阶段剩余工作是在正文切片上增加文化语义字段。

在现有文档、案例和事件阶段字段基础上，评估增加：

```text
cultureTheme：所属文化主线
practice：可观察到的具体做法
mechanism：做法如何运行
valueMeaning：它可能体现的价值取向
stakeholders：涉及员工、顾客、供应商或管理者
tension：现实限制、冲突或不同观点
effectiveAt：资料对应的时间
```

以上是内部结构，不在用户界面展示专业字段。

验收标准：

- 同一主题下能够对比企业自述、媒体观察和第三方分析；
- 具体事件不能因为标记了文化主题而被用来裁定整个文化真伪；
- 现行制度和历史资料能够按时间区分；
- 旧知识片段迁移后原有测试继续通过。

### 阶段 R3 — Query 改写 V1

**目标：** 让普通网友不必使用知识库中的标准词汇。

> 2026-08-01 用户明确要求提前处理其中的上下文、终局意图与资料不足噪声。该受限子阶段已完成并保留 28/54 冻结基线作对照；错别字修正、同义词扩展和完整 Query 改写仍未完成。

第一版优先采用可测试的规则与领域词表，不增加额外模型调用。

能力范围：

- 结合前文，把“那后来呢”补成独立问题；
- 保留上一轮的事件或文化主题；
- 扩展经过审核的同义词；
- 修正常见错别字；
- 从口语问题中提取事件、主题和最终结论意图；
- 同时保留原始问题，避免改写偏离用户意思；
- 改写失败时安全回退到原问题。

验收标准：

- 评测集中直接问题召回保持稳定；
- 追问和同义表达的正确召回明显提高；
- 不增加跨案例误召回；
- 无资料问题仍然能够明确拒答；
- 最终结论边界测试 100% 通过。

### 阶段 R4 — 文化型回答结构

**目标：** 从“资料复述”升级为“帮助理解”。

一般文化问题采用：

```text
直接回答
→ 一两个具体做法
→ 背后的文化逻辑
→ 资料归因
→ 必要的边界、现实限制或不同观点
```

热点事件问题采用：

```text
发生了什么
→ 企业公开怎么处理
→ 目前有没有后续结论
→ 这件事可以怎样检验企业文化
→ 不用文化口号裁定具体客诉真伪
```

验收标准：

- 不向普通用户暴露 L1/L2、`caseId`、`finality` 等内部术语；
- 不只堆来源或免责声明；
- 不将媒体、图书观点改写成企业官方事实；
- 不把回答写成单向赞美；
- 能自然呈现证据、质疑、限制和文化理解。

### 阶段 R5 — 关键词与向量混合检索

**前置条件：**

- 已有 30～50 份批准资料；
- 六条文化主线和知识字段基本稳定；
- R0 评测集能够重复执行；
- Query 改写 V1 已有基线对照；
- 错误召回和最终结论边界已有自动测试。

职责分工：

- BM25：处理精确词、门店名、事件名、制度名；
- 向量检索：处理语义相近但措辞不同的问题；
- 案例路由：锁定具体事件，避免跨事件混用；
- 重排与过滤：综合来源范围、主题、时间和回答边界选择资料。

验收标准：

- 使用同一套评测集比较 BM25 与混合检索；
- 语义问题的召回提升；
- 精确问题不能因向量相似而变差；
- 不能用向量相似度绕过 `approved` / `limited` 和案例边界。

### 阶段 R6 — 真实用户试用

邀请 10～20 位不了解项目内部结构的用户自由提问。

重点记录：

- 用户真正好奇的问题；
- 完全没有资料的问题；
- 太像资料说明、没有帮助理解的回答；
- 只做赞美、没有呈现边界的回答；
- 质疑性问题是否得到公平回应；
- 来源链接是否真的支持回答；
- 用户阅读后是否更能解释“自由与爱”如何落实。

试用结果形成下一轮资料补充、检索和回答优化清单。

### 阶段 R7 — 稳定发布与持续更新

- 本地修改、测试、用户验收后再重新部署；
- 自动搜索或定时监测只能生成候选资料；
- 新资料继续执行候选、审核、用户批准、入库、测试和部署流程；
- 对会变化的制度、门店和经营信息记录核验日期；
- 正式域名和 ICP 备案按用户确定的上线节奏另行推进。

## 6. 协作分工

### Codex

- 维护文化地图、知识结构、评测集和检索代码；
- 把用户批准资料转换为文化知识卡片；
- 实现 Query 改写、混合检索和回答边界；
- 运行测试、记录基线、更新 HANDOFF 并部署；
- 不得把 Grok 的审核建议视为用户已经批准。

### Grok

- 按文化主线广泛寻找候选资料；
- 核实企业身份、原始出处、发布日期、转载关系和事件阶段；
- 寻找相反材料、现实边界与不同观点；
- 输出候选卡片和审核建议；
- 独立复核评测结果、检索误召回和改动 diff；
- 不得未经用户批准直接写入正式知识库。

### 用户

- 决定文化主线优先级；
- 批准、限制或拒绝候选资料；
- 判断回答是否真正帮助理解，而不是只有技术正确；
- 参与试用验收并决定发布时机。

## 7. 当前立即执行项

阶段 R0 已完成：文化地图、54 道试卷、可重复运行的 BM25 基线和三类失败清单均已建立。基线为 28/54（51.8%），详见 `docs/RAG_CULTURE_BASELINE_V1.md`。

下一步继续阶段 R1/R2，并保留已完成的 R3 受限子阶段：

1. 保留当前基线，不用修改评测预期或检索算法美化分数；
2. 依据 15 道资料缺口题，有针对性补齐六条文化主线的一手资料，所有新增来源继续经过用户批准；
3. 为知识片段增加“做法—机制—价值—张力—时点”等文化字段；
4. 字段稳定后继续完成错别字修正、同义词扩展和完整 Query 改写 V1，并用同一套 54 道题重跑对照；
5. 无答案保护、案例隔离和终局边界稳定后，再进入关键词与向量混合检索。

当前不提前接入向量库，不批量抓取无主题资料，也不为了增加数量降低来源标准。
